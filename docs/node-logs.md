# 节点日志查看

本功能随 v1.18.0 提供，需要同时更新管理服务、管理端和节点 Agent。旧 Agent 不支持查询时，页面会超时并提示检查版本。无需升级业务 SDK。

## 应用如何接入

- 已经写 stdout/stderr：更新 Agent 后可直接查询 Docker 当前保留的日志，无需重启应用。
- 只写容器内部文件：将应用日志输出改为 stdout/stderr（由应用自身配置实现），仅 restart 不会自动接入。
- JSON 并非强制；纯文本和多行堆栈均可显示。推荐一行一条 JSON，时间采用带时区的 RFC 3339 UTC，字段为 `timestamp`、`level`、`message`，按需增加 `trace_id`、`service`、`version`。异常堆栈建议放入 JSON 字符串。

```json
{"timestamp":"2026-11-09T10:00:00.123Z","level":"error","message":"upstream request timed out","trace_id":"example","service":"notes","version":"v1.2.0"}
```

应用不要输出密码、Token、完整请求鉴权头或配置明文。管理端按文本展示原始业务输出，不保证自动脱敏。日志权限等同该项目/环境的部署解析权限（owner 或被授权的 deployer），publisher 不因此取得日志权限。

## 管理端查看

进入项目 → 部署：实例行点“运行日志”，任务行点“部署日志”。选择当前运行日志、历史运行归档、部署过程或最近失败快照；按需查询、刷新、设置时间范围/关键词并下载当前结果。

默认最近 200 行，最多 2000 行、256 KiB。关键词只在本次读取范围内匹配，不是遍历所有历史日志的全文搜索。当前运行日志时间以 Docker 加的采集时间为准；部署过程采用 JSONL 时间戳。旧失败快照可能没有时间戳，使用时间筛选时这些行会被排除。未匹配和读取失败分别显示，截断会明确提示。下载只包含当前结果。

历史归档标明版本及采集时间。最近失败快照为实例级最后一次失败的现场，不一定对应选中的任务。旧任务仅有内部执行记录，不会自动补成过程日志。

## 存储与生命周期

- 当前日志由 Docker 保存；标准发布包已有 `json-file`，`max-size=10m`、`max-file=3`。已有容器保持原设置；调整 Compose logging 后需通过 ctl 重建容器，普通 restart 不会应用 logging 配置。
- 归档及任务过程位于 `<部署根目录>/<项目>/<环境>/logs/`，默认根目录 `/opt/deployments`。目录 0700，文件 0600。
- ctl 在替换/移除容器前抓取 Docker 仍可读取的输出；包括升级、回滚、失败恢复。每份归档保留最近 10 MiB，最多 30 份；任务 JSONL 每份最多 1 MiB，最多 100 份。默认 7 天，写入或查询该实例时清理过期项。
- 归档是替换前的有限快照，不是持续采集：Docker 已轮转删除的内容、替换过程最后产生的输出、人工 `docker rm` 前未归档的内容无法保证保留。已经删除的旧容器无法补回。
- 日志归档失败不会阻止应用部署，会记录告警；磁盘不可写时日志自身也可能无法写入。
- `/var/lib/ctl-agent/tasks` 仍是防重复执行的内部持久记录，不参与诊断日志轮转，不能手动删除以重试任务。

## 通信与运维

中心不保存日志正文、不写数据库、不定时拉取。查看器发起请求后，节点的独立只读长轮询线程领取查询并回传；节点无需开放入站端口，也不占部署队列。中心只在请求生命周期内使用内存，关闭/取消或超时即移除；最多等待 25 秒，最多 64 个并发查询、每节点最多 2 个。

查询范围由中心按实例/任务归属与最新权限决定，节点仅使用受管项目、环境和固定日志来源，不接受任意路径、shell 或外部容器 ID。用户权限在查询前和响应前复查，节点交付时也复查授权。

当前中转适用于现有单管理服务部署。若未来将管理服务扩展为多副本，需要先增加按节点路由/共享临时请求机制；不能直接将这些端点随机负载均衡。中心重启会取消正在查看的请求，重新查询即可，不影响节点日志。
