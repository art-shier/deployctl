# Console system updates

User approved implementation of node Agent updates and center updates from the console. Existing production release v1.14.0 is baseline; this work does not publish or upgrade a live host. Code version for the new capability: CLI 1.15.0 / Web 0.8.0.

## Architecture and trust

- Separate Linux root systemd services run private copied CLI zipapps. Integrated installs default to `/var/lib/ctl-updater-node` + `ctl-updater-node.service` or `/var/lib/ctl-updater-center` + `ctl-updater-center.service`; advanced legacy defaults remain compatible. It survives replacement of the managed CLI and center containers. It has a dedicated updater identity, never an owner credential. All control traffic is outbound HTTPS (loopback HTTP only for development).
- Normal installation exchanges a 15-minute one-use enrollment token automatically, using the existing local node identity or the center local owner identity. Node credentials can request only their own target through `/node/updater-enrollment` and cannot access owner routes. Center bootstrap uses loopback transport while persisting the actual center origin, never the owner token. Advanced owner API can still create a token bound to `{kind:node,target_id:<existing node id>}` or `{kind:center,target_id:center}`. No generic shell, remote path, command or arbitrary download URL is accepted. One updater per target. Rotation/replacement must reject active update jobs and invalidate the old credential.
- Local setup fixes CLI executable, Agent home/unit or center home; server tasks never override these paths. Enrollment copies the current zipapp to updater home, persists private identity/config, and provides install/systemd instructions. Normal node `agent install` and center CLI `server install/upgrade` configure the helper automatically; existing installations can use credential-free setup with saved identities. Repeat installation reuses matching config; no second operator registration or credential prompt. Center updater Host calls deploy_server directly and never recursively configures its own helper.
- Releases come only from official `art-shier/deployctl` non-draft, non-prerelease GitHub Releases. Only stable semver >=1.15.0 and <2.0.0 is eligible for protocol 1; no downgrade or same-version task. Catalog pins published CLI and server-bundle SHA256. Helpers independently use fixed official release URLs and verify pinned digest + embedded version. No latest alias in tasks.
- Published updater bootstrap stays independent of updated CLI. Protocol 1 compatibility is an explicit release contract; breaking protocol requires a deliberate local bootstrap upgrade. Node Agent publishes a local private freshness/version readiness marker after a successful center heartbeat; updater uses a marker newer than restart to validate the new process, plus systemd active state. Center verifies installed server-state version, no pending operation, and API ready endpoint. Platform version is taken from installed server state, not helper version.

## HTTP contract (all paths prefixed /api/v1)

Owner-only:

- GET `/system-updates/releases` => `[{version:"v1.16.0",published_at:"...",cli_sha256:"...",server_sha256:"..."}]`. Bound catalog to 10 eligible releases, HTTPS timeout/size limits; cache briefly, return errors explicitly. Injectable provider for tests. Owner can refresh by reload; do not expose arbitrary artifact sources.
- GET `/system-updates` => `{updaters:Updater[],jobs:UpdateJob[]}`. All blocking jobs plus the latest 200 nonblocking history records. Updater fields: `id,kind,target_id,current_version,helper_version,protocol,platform,ready,blocked_reason,last_seen,online`. Node names loaded from /nodes. Unenrolled nodes remain visible there with setup guidance.
- POST `/system-updates/enrollments` `{kind,target_id}` =>201 `{enrollment_token,expires_at}`; bound tokens exchanged atomically.
- POST `/system-updates/jobs` `{request_id:<32hex>,updater_ids:[ids],version:"vX.Y.Z",parallelism:1,backup_confirmed:false}` =>201 `UpdateJob[]`. Max 50 unique node IDs, parallelism1..5; center alone, `backup_confirmed:true` required (UI explanation: helper will take DB/config backup; large image/artifact backup remains administrator responsibility). Idempotent request ID + request hash, conflicting reuse409. No duplicate active task per updater. Require ready, online(<90s), protocol1, strictly newer compatible release. Freeze digests, source version and batch/parallelism in task; repeated request must not refetch changed release.
- POST `/system-updates/jobs/{id}/cancel` {} => job; only queued may cancel. Audit enrollment/job/cancel operations with no raw credentials.
- POST `/system-updates/jobs/{id}/resolve` {} => job; only needs_attention, requires online ready protocol1 updater heartbeat newer than terminal job updated_at and observed current_version equal to from_version or version. Idempotently set resolved_at, preserve original status/report. Audit explicit recovery acknowledgment. Unresolved needs_attention blocks future jobs and deployments; resolved jobs do not. No auto-unblock on heartbeat.

Dedicated updater API:

- POST `/updater/enroll`, Bearer enrollment token, `{helper_version,platform,protocol:1}` => `{updater_id,token,kind,target_id}`.
- POST `/updater/heartbeat`, Bearer updater token, `{current_version,helper_version,protocol:1,platform,ready,blocked_reason}` => `{enabled:true}`. Use fixed bounded reason codes, not raw command output. Empty current_version allowed for unready setup. Disabled/pending node may not get upgrade leases. Updater identity cannot access owner/node routes.
- POST `/updater/poll` {} => `{job:UpdateJob|null}`. Transactional exclusive lease; repeated poll of leased/running returns same job. No automatic reexecution after restart. `start` checks current identity and state, queued cancellation cannot race execution.
- POST `/updater/jobs/{id}/start` {} => job; leased->running before local destructive work.
- POST `/updater/jobs/{id}/report` `{status,stage,result_code,current_version}` => job. Idempotent immutable terminal reports. Reject cross-updater identity, unknown stages, raw logs. Statuses: queued,leased,running,succeeded,rolled_back,failed,needs_attention,cancelled. Stages: queued,waiting,downloading,backing_up,stopping,installing,restarting,verifying,restoring,completed,failed,interrupted. result_code bounded fixed values: ok,download_failed,backup_failed,install_failed,health_failed,rolled_back,interrupted,manual_recovery_required. Terminal reports include observed installed version; no credentials/paths.
- UpdateJob fields: `id,request_id,batch_id,updater_id,kind,target_id,version,from_version,cli_sha256,server_sha256,status,stage,result_code,current_version,created_at,updated_at,parallelism,resolved_at`.

## Scheduling and failure rules

- Queued/leased/running/needs_attention jobs suspend new business task leases for affected nodes; center job suspends new leases globally. Existing leased/running business tasks may finish. Updater lease waits until relevant leased/running business tasks have ended. Serialize against existing node task leasing with a shared advisory lock or consistently ordered locks. Never stop an Agent running a deployment. Queued node batch updates are leased with batch concurrency <=parallelism; center never overlaps any active node update and vice versa.
- On task start ambiguity/restart, rely on private durable journal before actions. Never blindly replay execution. Preserve terminal outcomes locally and retry reports until acknowledged, including after center replacement/network loss.
- Node: download/validate first; snapshot installer-managed executables and metadata to private durable backup; stop known Agent unit gracefully; ensure process fully stopped; replace CLI via existing installer semantics, restart; validate fresh marker + actual version within bounded deadline. Failure restores exact old files/metadata and restarts old service. Verify recovery before reporting rolled_back, otherwise needs_attention. Keep task evidence and backup. Do not modify application instances/data/credentials.
- Center: only installed managed server, reject pending operations initially. Prepare verified server bundle, backup DB plus keys/instance/compose/server-state using local fixed configuration. Built-in database via known Compose exec pg_dump; external DB via installed pg_dump with URL supplied privately in environment (not shell args/logs). Backup failure prevents upgrade. Run existing deploy_server pinned bundle/digest; do not automatically roll back schema. On restart reconcile server-state + ready endpoint; if ambiguous report needs_attention and preserve installer pending state and backup. After local repair and fresh ready heartbeat, owner explicitly acknowledges recovery via resolve. New jobs remain strictly newer than actual installed version; no automatic destructive retry.
- No arbitrary shell execution. Validate root-owned/non-writable parents, symlinks, executable installer metadata and bounded inputs before privileged filesystem or systemd operations. Serialize updater execution with durable per-home lock; do not modify updater identity when running/unfinished journal exists.

Show center and node updater targets with version, connectivity, readiness, setup guidance, available releases, batch selection, fixed target version, sequential default concurrency, pilot recommendation. Center confirmation explains brief console outage, database backup, no automatic schema rollback. Updater credentials are not generated or shown in the Web normal workflow. Installation help explains automatic setup and credential-free repair commands. Initial node onboarding still uses its original one-time hidden credential prompt; secrets never enter command lines/URLs/browser storage. Non-secret uncertain request identity/payload is retained across navigation in validated session storage and reconciled against refreshed history; enrollment credentials never enter storage. No deployment controls for non-owner identities.

## Agreed CLI and wire details

`sudo ctl updater enroll --server URL --kind node|center --target-id ID --cli-path /usr/local/bin/ctl [--agent-home /var/lib/ctl-agent --agent-service ctl-agent.service | --server-home /opt/ctl-platform] [--home /var/lib/ctl-updater]` uses hidden input or `--token-file` private file. `sudo ctl updater install --home /var/lib/ctl-updater` installs/enables helper systemd unit; `run` runs foreground and `service` prints unit. Enrollment binds and verifies expected kind/id before accepting identity.

Wire versions canonical v-prefixed; platform linux; protocol1. Fixed blocked_reason: empty, setup_required, unsupported_platform, unsupported_protocol, invalid_version, agent_unavailable, pending_operation, service_unavailable, disabled, pending_authorization, backup_unavailable. Current source version may predate1.15, helper requires1.15+.

## Integrated installation correction (user confirmed)

Normal node command is `sudo ctl agent install --server URL`, prompting only when node.json is absent. Existing node `sudo ctl agent install` reuses identity, installs/starts Agent and updater, and refuses mismatched unit/home/server. Normal center `server install/upgrade` automatically configures helper only after deployment succeeds, using existing local keys/owner.token through loopback. `updater setup --kind node|center` derives target/origin locally and is a credential-free repair entry. Preserve role-specific homes/services on the same host. Report partial success truthfully if the primary service is installed but helper setup fails; preserve state and allow safe retry. No weakening root ownership, active-job or unfinished-journal guards.

Node own-only `POST /api/v1/node/updater-enrollment {}` returns the same internal one-use token/expiry shape as the owner enrollment API. Derive target from authenticated node, recheck credential under the node row lock, reject caller-selected targets and active unresolved updates; pending authorization does not require a second enrollment, while lease authorization remains enforced.
