# ctl 项目管理与发布凭据配置权限

用户要求发布密钥能够读写项目配置、新建和管理项目；部署密钥权限保持不变；超管可以新增和删除项目、项目组。现有管理台与 CLI 共用 API，旧发布和部署流程继续兼容。

## 角色与范围

| 操作 | 发布凭据 | 部署凭据 | 超管 |
|---|---|---|---|
| 查看授权项目、版本、拉取镜像 | 保持现有能力 | 保持现有能力 | 全部 |
| 发布版本、推送镜像 | 保持现有能力 | 不允许 | 全部 |
| 新建项目 | 授权项目组内，排除项目仍优先拒绝 | 不允许 | 全部 |
| 修改项目资料 | 授权项目内 | 不允许 | 全部 |
| 项目环境配置读写 | 授权项目内；显式环境范围非空时受限 | 保持既有部署读取能力，不新增管理端配置读写 | 全部 |
| 移动、删除项目 | 不允许 | 不允许 | 允许 |
| 新增、修改、删除项目组及组配置 | 仅能列出自身授权组 | 保持既有能力 | 允许 |
| 创建、编辑、查看、撤销访问凭据 | 不允许 | 不允许 | 允许 |

`owner` 为现有全局超管密钥/会话，不额外创建新的提权角色。项目单独授权不等于获得所在项目组的新建权限。现有发布凭据无需重新签发即可获得其授权项目范围内的新能力。

publisher新建项目使用平台RegistryHost/slug标准路径；不能修改镜像仓库绑定，也不能利用预先绑定到未授权或归档项目的标准路径扩大镜像权限。owner保留指定/共享镜像路径的能力，相关创建、绑定修改、移组、归档与镜像操作共用仓库锁。创建初始环境或修改默认环境须符合publisher配置环境范围。凭据编辑切换角色不应静默清空已有环境限制。

## 配置接口与 CLI

项目环境列表、单环境 GET 和 PUT 允许有权限的 publisher 和 owner。默认回复仍隐藏秘密值，`?reveal=true` 明确返回自身和继承变量中的真实值；读取秘密记审计，不记录内容，回复禁止缓存。组配置读写及读取秘密仍仅限 owner。

继续使用现有 `expected_revision` 和 `set/keep/remove` 变更协议。服务端必须在配置读写事务或同一快照内检查项目当前归属，不能依赖登录时扩展的旧项目组列表。移组与读写并发时，不得泄露或覆盖未授权组的数据。发布、部署凭据都保留原有排除项目规则。

发布文件上传结束后，需在发布事务锁定的当前项目归属下再次授权，失败时不得访问Registry、落盘制品或修改stable。Registry新授权同样使用当前列表归属判断。

CLI 增加 `project`、`group` 管理命令以及 `project-config`、`group-config` 配置命令，保留 `projects` 和 `config get/set server`。配置读取默认遮盖秘密，`get --reveal` 才显示；配置写入支持单变量设置/移除和私有 JSON 文件批量变更。密码支持私有值文件输入。写入结果不回显秘密；409 保留冲突，不自动重试覆盖其他人的编辑。

## 删除与数据保留

超管 DELETE 项目/项目组采用归档标记，返回204。活动列表、配置、发布、解析与后续 Registry 授权中排除归档对象；保留原始配置、发布包、镜像文件、历史凭据范围和审计。项目标识保留，不能复用，避免旧凭据重新获得新对象的权限。

只允许删除空项目组；已经归档的项目不阻止组删除。保留默认项目组以维持旧客户端和默认新建行为。项目删除不会执行远程 Docker 停止或卸载；已安装业务服务继续运行，后续托管发布/部署请求失败。已签发 Registry bearer 仍遵循已有最长五分钟到期。

管理台增加明确的删除入口、输入标识确认、空组限制说明和失败状态。凭据授权范围中已归档的组/项目应可辨认并移除，避免编辑时出现隐藏的无效范围。

## 验证

真实 PostgreSQL 验证角色矩阵、范围/排除项、显式环境限制、移组并发授权、配置版本冲突、删除与创建/移动的事务互斥、旧数据与审计保留。CLI 使用本地 HTTP API 或真实管理服务验证参数、默认环境、秘密输入/显示、写入失败与删除确认。管理台验证删除取消、确认、错误、空组与默认组边界。集成测试验证发布凭据操作配置和创建项目，部署凭据仍只能按原权限部署，超管操作完整 CRUD。
