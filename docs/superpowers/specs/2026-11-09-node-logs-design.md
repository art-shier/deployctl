# 节点按需日志

用户已授权按建议直接实施。日志留在节点，中心只在查看期间中转，不落数据库、不后台同步正文。复用现有 Python Agent、Go 服务和 React 管理端，不开放节点入站端口。

## 方案
采用独立只读查询轮询：浏览器请求中心，Agent 独立工作线程领取短期查询并返回，中心同步回复浏览器。查询不占部署任务队列。相较中心主动连节点，此方案兼容现有网络；相较集中采集，不引入持续传输和中心存储。

运行日志读取受管 Compose app 容器 stdout/stderr，兼容纯文本，推荐应用 JSON 单行格式。重建/回滚/失败恢复前在节点保存有限大小的旧容器日志快照及版本、容器、采集时间。已删除日志不能恢复，Docker 轮转前已丢失的数据不能恢复。外部手工 docker rm 不在 ctl 归档保证范围内。

部署日志按远程任务记录 JSONL 时间、级别、阶段和安全消息，并支持读取最近失败诊断。禁止记录平台凭据、配置全文或任意异常正文。业务日志保持原文，应用负责不输出敏感字段。

## 边界与默认值（实施选择）
每实例归档/部署日志最多保留 7 天、30 份归档和 100 份任务日志；单份归档最多 10 MiB，任务日志最多 1 MiB。查询默认 200 行，最多 2000 行/256 KiB，超限明确标识。支持时间范围、文本搜索、手动刷新和下载当前结果。不存在实时常驻 tail 或无限制全量导出。

只允许 owner 或具有项目环境 resolve 权限的 deployer；校验实例/任务/节点归属和最新节点授权，禁止任意路径/命令。查询等待最多 25 秒；中心最多 64 个、每节点最多 2 个待处理查询，取消/超时即删除内存请求。节点离线和旧 Agent 不伪装成空日志。

管理端在现有部署页实例/任务旁提供日志入口，复用现有视觉和请求工具，查看器标明节点、环境、来源、截断和历史采集时间。切换来源、关闭和切换项目取消旧请求。

## 接入
现有 stdout/stderr 应用不需要 SDK 或业务重启；升级管理端与 Agent 即可查看保留下来的输出。仅写容器文件的应用需改为 stdout/stderr。新增容器日志配置需重建而非普通 restart。历史归档和任务过程记录从新版启用后开始。
