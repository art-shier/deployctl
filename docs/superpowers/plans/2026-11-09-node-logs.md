# Node Logs Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Node-local runtime and deployment diagnostics with on-demand admin viewing.
**Architecture:** Bounded local log storage, independent outbound query polling, ephemeral in-memory HTTP relay, existing deployment UI entry points.
**Tech Stack:** Python stdlib, Go/net/http/PostgreSQL authorization, React/TypeScript.
**Spec:** docs/superpowers/specs/2026-11-09-node-logs-design.md

## Global Constraints
No central log persistence, arbitrary paths, inbound node ports or continuous shipping. Existing stdout/stderr applications need no SDK. Query 200 default / 2000 max lines / 256 KiB; archive 10 MiB; task 1 MiB; seven days / 30 archives / 100 tasks. Existing deployment semantics remain authoritative.

## Review Focus
- Permissions revoked while query waits: revalidate before handing over and returning data.
- Deployment in progress: independent query worker, no deployment lock.
- Huge/binary logs: bounded memory and output, replacement decoding and truncation indicator.
- Recreated containers: archive before replacement, including rollback and recovery.
- Stale UI response: abort on target/source change and unmount.
