# 版本登记

从 1.17.0 起，中心以 PostgreSQL 中的登记记录作为系统更新版本列表。查看和刷新列表不向 GitHub 发起请求，不需要配置 S3 或额外的下载域名。

## 发布时自动登记

1. 管理员进入「系统更新 → 可用版本 → 流水线登记接入」，生成专用凭证并复制。凭证仅在本次弹窗显示，中心只保存其哈希。
2. 在发布仓库 Settings → Secrets and variables → Actions 中配置 Variable `CTL_CENTER_URL` 为中心 HTTPS 地址，Secret `CTL_VERSION_REGISTRATION_TOKEN` 为该凭证。
3. 后续 Release 完成发布和验证后，流水线自动调用中心登记接口。未配置中心地址时跳过该步骤。

GitHub Actions 必须能访问中心。凭证只能登记版本，不能管理项目、创建升级任务或访问管理员接口。轮换后旧凭证立即失效，需要同步替换仓库 Secret；撤销后不能继续登记。

登记步骤最多尝试 5 次。网络故障、限流或中心不可用时，已发布的 Release 不会撤销，但工作流会明确失败。恢复后在 Actions 中运行 **Register released version**，填写已发布版本号，例如 `v1.17.0`；无需重新构建或再次发布。不要重新运行整个发布流程来补登记。

脚本读取正式 Release 的已校验 `update-index.json`，使用其中固定的发布时间和摘要，保证与首次导入和重复执行一致。中心凭证只发送给中心，登记请求拒绝重定向。

## 手动登记

进入「系统更新 → 可用版本 → 登记版本」，填写版本号、发布时间、CLI 更新包和中心安装包的 HTTPS 下载地址及 SHA256。

- CLI 包为 `deployctl.pyz`；中心安装包为 `ctl-platform-vX.Y.Z.tar.gz`。
- SHA256 来自各安装包对应的 `.sha256` 文件；不要填写文件名。
- 「填入 GitHub 下载地址」可补齐官方地址，也可填写自有可访问的 HTTPS 文件地址。
- 保存只记录元数据，不下载文件、不执行更新；保存后版本即可选择。
- 相同版本、地址、摘要和发布时间重复登记返回成功；同版本不同内容返回冲突，不覆盖已有记录。手动补录官方版本时使用该版本 `update-index.json` 中的发布时间，避免之后流水线登记冲突。

首次安装或升级到本版本时，中心会自动导入镜像内置和本地已有清单。内置清单只包含镜像构建前已发布的版本；当前版本可通过流水线或手动登记补齐。数据库持久化存储应保留并纳入备份。

## 版本可见与实际下载

登记解决的是版本发现问题。实际更新仍须能下载安装包；中心安装包不包含 Docker 镜像，中心宿主机还需访问包内指定的镜像仓库。

1.17.0 及以上更新器从中心获取任务对应的安装包，由中心下载、校验 SHA256 并缓存；节点不需要直接访问安装包站点。任务创建时固定地址和摘要，下载失败不会自动改用其他来源。

旧更新器仍按原机制下载官方 GitHub 地址。使用自定义下载地址前，需先将相应宿主机的 ctl/更新器升级到 1.17.0；管理端和后端会阻止旧更新器执行这类任务。网络受限时可使用现有离线安装包升级方式完成这次过渡。
